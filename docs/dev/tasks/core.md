# Core tasks (Dev A, branch `feat/core`)

Owns the accuracy path: data → understand → match → decide → reply → check → batch. File globs are in
[contracts.md §4](contracts.md). Read SPEC §1, §3, §4, §6, §12 and DEMO §1 and §3 before starting.

## How to build (every task inherits this)
- **Isolation:** one module per concern, with pure functions at the stage seams ([contracts §2](contracts.md)).
  I/O happens only in `data.py`, `db.py`, `api/` (and `llm/` for model calls). Thresholds and limits live in `config.py`
  with env overrides, so a demo tweak is one line.
- **Easy to modify:** small typed files, no cleverness. A new category, rule or queue means a new table or dict entry
  (channel families, score weights, policy rules, template keys), not edits across many files.
- **Verify APIs:** typings (`backend/.venv/Lib/site-packages/<pkg>`) → ctx7 → a probe you run. For any other open
  question (regulatory facts, UX patterns, unfamiliar errors), web search ≤3 queries and cite the URL in your report.
- **Tests at seams**, with regressions taken from real IDs: CMP-00165, CMP-00244, CMP-00387, CMP-00289 (LIVE-07 belongs to
  Platform). Money is `Decimal`; the LLM never decides outcome, refund, route or priority.
- **Scope:** build only what DEMO.md touches and note anything else as cut. After two failed attempts, stop, narrow the
  task and report. The lead commits before spawning worktree builders; a builder commits its task on its worktree branch.
- **Report:** files changed, what is cut, any contract or package requests, then one `Verified:` line per check.

`B` = `cd backend &&`. Waves run in order; tasks in one wave share no files and can run as parallel builders (max 3).
